Executive verdict

适合显存受限部署，不替代 resident 快路径

在这组硬件和模型 shape 上，逐层权重传输的大部分成本被当前层计算覆盖， 观测上以约 0.10% 的 matched-eager 中位延迟差换得约 34% 的峰值显存下降。 显存充足时仍优先使用 CUDA Graph resident；需要释放约 3.37 GiB GPU 容量时，再启用 layer-wise offload。

0.10% 小于单次 run 内约 9–10 ms 的状态阶跃，不能视为统计显著回退； 当前证据支持的表述是“稳态性能基本持平”。

ready_event 保证 copy 完成后才能计算； reusable_event 保证计算完成后才能覆盖 slot。 固定两个 slot 避免异步深队列把临时权重扩张成整网显存。 默认完整 chunk 包含约三次 DiT，因此理论上传输约 10.8282 GiB block weights；本次未采集 H2D profiler telemetry，不能断言传输被完全隐藏。

初始化

  1. CPU 创建网络并加载真实 checkpoint。
  2. 执行 load-time 权重变换。
  3. 逐 block 打包至 pinned host buffer。
  4. 原 Parameter 保持 identity，但绑定为空 placeholder。
  5. 父 pipeline 移到 CUDA 时不再搬运整套 block 权重。

覆盖的参数访问路径

  • 普通 DiT block forward。
  • cross-attention KV-cache 初始化。
  • 替换 text embeddings 后重算 cross-attention KV。

非 block 权重、KV cache 和 activation 仍然常驻 GPU。

04 · Methodology

稳态 recurring chunk，而非 UI 端到端延迟

计时范围

  • 每个 chunk 的 HDMap Wan/LightVAE encoder。
  • 两次 DiT denoising forward。
  • TAEHV/LightTAE decode。
  • KV-cache finalize；它会再执行一次 DiT forward。
  • CUDA synchronize，确保报告的是完成时间。

明确排除

  • 一次性文本编码和首帧图像编码。
  • checkpoint 加载和 pinned-buffer 构造。
  • CUDA Graph capture、首次可见帧和启动时间。
  • UI、WebRTC、MP4 编码及呈现队列。

输入为长度 512 的全零 text embedding、全零 initial-image embedding，以及 seed 0 生成的固定随机 BF16 HDMap。先填满 attention window，再执行 5 个 warmup chunks 和 20 个 measured chunks。三种模式各自在新进程中运行，避免 CUDA caching allocator 污染 reserved-memory 对比。

数值一致性

三个受控 final chunk 的 mean、std 和 SHA-256 完全相同。这证明本 case 的最终 tensor exact parity，不等价于真实场景的完整 rollout 质量评估。

06 · Constraints

当前兼容性边界

  • 仅用于单线程、immutable-weight 推理，不支持训练或运行时参数修改。
  • 不支持 DTensor、tied/storage-aliased parameters 或启用后的 dtype 转换。
  • OmniDreams offload 仅支持标准 OmniDreams self/cross attention backend。
  • 整网 torch.compile 和 CUDA Graph 会被关闭。
  • 不兼容 native DiT acceleration 和 runtime text-edit LoRA。
  • offload 后 state-dict save/load fail-fast，应重新加载原 checkpoint。
本报告是单一 H20-3e stack 的证据，不应直接外推到其他 GPU、PCIe 代际、 NUMA 拓扑或模型规模。

3.6094 GiB 是 offloader 所分配 host buffer 的字节数，不是进程 host RSS； reserved GPU memory 是测点值而非 peak-reserved，也不等同于 nvidia-smi 的整卡占用。
